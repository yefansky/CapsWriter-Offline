# 安装、更新与绿色版

CapsWriter-Offline 有两种官方使用方式，模型在两种方式中都不会预先塞进安装包。

## 普通用户：安装版

1. 打开 GitHub Releases，下载 `CapsWriter-Offline-Setup.exe`；
2. 双击安装。它只安装到当前 Windows 用户目录，不要求管理员权限；
3. 从桌面或开始菜单打开 “CapsWriter Offline”；
4. 第一次运行时，如缺少当前选择的识别模型，管理器会自动下载、校验并安装；下载进度在“运行日志”页可见；
5. 以后进入管理器的“系统设置 → 软件更新”，点击“检查更新”。确认后程序会下载最新安装包、核对 SHA-256、安装并自动重启。

软件更新不携带模型，因此通常比首次安装小得多。模型下载中断不会重头开始，重新启动即可续传。

## 绿色版：解压即用

1. 下载 `CapsWriter-Offline-Portable.zip`；
2. 解压到任意有写入权限的目录，例如 `D:\\Apps\\CapsWriter-Offline`；
3. 双击目录中的 `run.bat`。

绿色版已经带好 Python 运行时和可执行程序，不需要安装 Python、不写注册表、不创建卸载项。首次运行同样会自动下载模型。

绿色版的“检查更新”会告诉你最新 Release 的位置，但不会自动覆盖原目录：热词、配置和源码都可能被你改过，静默覆盖会丢数据。要更新绿色版，请下载新的 ZIP 并解压到新目录，再按需迁移 `hot*.txt`、`capswriter-settings.json` 和模型目录。

## 源码运行：保留开发体验

从 Git 仓库取代码后，仍可直接双击 `run.bat`：

- 如果目录里有打好的 `start_manager.exe`，它直接启动，不安装 Python；
- 纯源码目录没有 exe 时，脚本会创建 `.venv`、安装项目依赖，再启动管理器；
- 源码目录不会参与安装版的自动更新，也不会被更新器覆盖。开发者继续用 `git pull` 管理代码版本。

## 发布者：每次提交如何到达用户

向 `master` 推送一次提交，就会触发 GitHub Actions：

1. 运行单元测试；
2. 构建完整 Windows 绿色包和更新助手；
3. 生成当前用户安装包；
4. 上传绿色 ZIP、安装包和 `SHA256SUMS.txt`；
5. 创建一个新的 GitHub Release，并把它设为 Latest。

工作流只申请 `contents: write`，用于在当前仓库创建 Release。首次启用前请在仓库 Settings → Actions → General 确认允许工作流使用读写 `GITHUB_TOKEN`。

Windows 会对未签名的新安装包显示 SmartScreen 警告。SHA-256 校验能发现传输损坏，但不能替代 Authenticode 代码签名；后续配置代码签名证书后，应在工作流中增加签名与时间戳步骤。
